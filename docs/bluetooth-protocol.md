# OV-Watch 蓝牙文本协议

KT6368 使用经典蓝牙 SPP，把 STM32 USART1 的文本流透传给手机。命令必须按
原始文本字节发送，**不能追加 `\r` 或 `\n`**；固件按 UART 空闲中断划分接收，
并用完整字符串匹配命令。固件响应以 `\r\n` 结束。RFCOMM 是字节流，App 必须
先按行重组响应，不能假定一次 Android 读取就是一条完整响应。

## 兼容命令

- `OV`：固件回复 `OK`。
- `OV+VERSION`：固件回复 `VERSION=V<major>.<minor>.<patch>`。
- `OV+SEND`：保留原有多行遥测响应，不改变字段和顺序。
- `OV+ST=yyyyMMddHHmmss`：手表“日期时间”页面开启“同步APP”后生效，
  成功仍回复 `TIMESETOK`；仅收到 `RecStr:...` 回显不代表校时成功。

校时命令现在会验证固定长度、十进制字符、2000—2099 年范围和真实公历日期。
失败时返回单行 `OVERR|1|cmd=ST|code=<错误码>`：

- `SYNC_DISABLED`：手表“同步APP”开关关闭；固件不会绕过此安全开关。
- `INVALID_LENGTH`：命令不是精确的 20 字节格式。
- `INVALID_TIME`：日期或时间字段不是有效值。
- `RTC_ERROR`：RTC 写入或写后读取校验失败。

成功写入后，首页按原有刷新周期从 RTC 重新读取时间，不需要重启界面。

## `OV+DATA` 单行遥测

新增命令 `OV+DATA`。固件先保留现有的 `RecStr:OV+DATA` 调试行，然后发送一条
版本化遥测帧：

```text
OVD|1|ts=20261002T125806|temp=26|humi=61|hr=78|spo2=na|steps=3241\r\n
```

帧由 `|` 分隔：

- `OVD`：固定帧类型，表示 OV-Watch data。
- `1`：帧格式版本。App 只解析明确支持的版本。
- `ts`：手表本地时间，格式 `yyyyMMddTHHmmss`。
- `temp`：AHT21 环境温度，整数摄氏度，不是人体体温。
- `humi`：AHT21 环境相对湿度百分比。
- `hr`：最近一次缓存的心率值；当前固件只在心率页面测量，不代表连续心率。
- `spo2`：当前固定为 `na`，因为固件尚无真实血氧测量路径。
- `steps`：当日累计步数。

字段使用 `key=value`，键和值不得包含 `|`。v1 必需字段为 `ts`、`temp`、
`humi`、`hr` 和 `steps`；未知键可以忽略，重复键或格式错误的帧应丢弃。

## 能力探测

App 可发送 `OV+CAP` 探测本轮新增能力。支持时返回：

```text
OVCAP|1|data=1|clock=1|clock_sync=1|sw=1|swlog=1|swlog_cap=8|persist=0\r\n
```

`clock_sync` 是手表当前“同步APP”开关状态。`swlog_cap=8` 表示固件只保留最近
8 条已完成秒表记录；`persist=0` 表示记录只在 RAM 中，复位或断电后丢失。
旧固件不会返回 `OVCAP`，App 应超时降级到原有遥测和校时行为。

## 秒表状态与历史

`OV+SW` 读取当前秒表，不会远程控制手表：

```text
OVSW|1|boot=3141592653|sid=3|state=run|elapsed_ms=48210\r\n
```

- `boot`：本次启动标识。它混合 STM32 UID、RTC 日期时间/亚秒值和 RTC 备份寄存器
  启动计数，用于 App 去重；它不是密码学随机数，也不保证绝对唯一。
- `sid`：本次启动内的会话编号，从 1 递增；空闲时为 0。达到 uint32 上限后回到 1。
- `state`：`idle`、`run` 或 `pause`。
- `elapsed_ms`：当前累计毫秒数；达到 uint32 上限后饱和，不回绕。

离开秒表页面不会清零正在运行或暂停的会话。暂停不生成历史；在暂停状态点击复位，
且累计时长大于 0 时，固件只保存一次完成记录，然后清零会话。

秒表处于 `run` 时必须保留 1 ms SysTick 才能继续计时，因此固件会拒绝所有进入
STOP 深睡的请求；手动休眠键也不会让手表进入深睡。这个行为会增加运行中秒表的
耗电。先暂停秒表后仍可正常进入 STOP，固件不会为了省电自动暂停或结束会话。

`OV+SWLOG=<after>` 按 `sid` 升序返回第一条 `sid > after` 的完成记录：

```text
OVSL|1|boot=3141592653|sid=3|end=20261007T123045|dur_ms=48210|more=0\r\n
```

`more=1` 表示该条之后仍有可取记录，App 可把本次返回的 `sid` 作为下一次 `after`。
无后续记录时返回：

```text
OVSL|1|boot=3141592653|none=1\r\n
```

`after` 必须是 uint32 十进制数，否则返回
`OVERR|1|cmd=SWLOG|code=INVALID_AFTER`。首次同步使用 `OV+SWLOG=0`；断开蓝牙期间
只要手表未复位，重新连接后仍可补取最近 8 条。App 去重不应只依赖 `boot+sid`，建议
同时纳入设备地址、`end` 和 `dur_ms`，降低备份域丢失或极端编号回绕造成的碰撞风险。

## App 兼容策略

每次建立连接后，App 先发送 `OV`，等待 `OK`（最多 2 秒），确认后才开始采样，
避免握手命令与首条采样命令在 UART 接收中合并。首次采样先发送 `OV+DATA`。
若 800 ms 内收到且成功解析
`OVD|1|...`，本次连接继续使用新帧；否则发送 `OV+SEND`，并在本次连接剩余
时间使用旧协议。重新连接时会重新探测，因此固件升级后无需清除 App 数据。

握手、自动/手动采样和校时共用一条事务队列；前一条命令收到完整响应或超时后，
才执行后一条。采样等待完整 `OVD` 帧或旧协议的 `Step today:` 结束行；校时必须
等到 `TIMESETOK` 才报告成功。通常响应超时为 2 秒，首次新协议探测为 800 ms，
探测回退包含在同一采样事务内。校时超时会提示先开启手表“同步APP”。

每条命令响应结束或超时后再留 80 ms 恢复间隔，供固件完成共享 DMA 缓冲区清理。
断开或自动重连会取消正在等待的事务，并废弃旧连接排队中的命令；旧命令不会发到
重连后的手表。超时会释放队列，后续请求仍可继续执行。

## 当前限制

- USART1 接收使用 25 字节 DMA 缓冲区，现有命令以及最长的
  `OV+SWLOG=4294967295` 均在此范围内。
- 发送走阻塞式 UART 输出；上面的示例帧约 73 字节，在 115200 baud 下线速
  时间约 6.4 ms，尚未做真机时序测量。
- 接收 ISR 与消息任务共用原有 DMA 缓冲区。手机连续无间隔发送多条命令时，
  存在合并或后一条覆盖前一条的窗口，真机曾观察到采样与连续校时命令串接。
  App 现通过响应驱动的串行事务和恢复间隔规避；其他调试工具仍需避免连续发命令，
  固件完整接收队列尚待改进。协议不带请求编号，极晚的同类响应无法严格关联请求。
- 电量、海拔和罗盘虽有缓存字段，但只在特定 UI 更新路径刷新，暂不放入 v1，
  以免把默认值或陈旧值展示为实时数据。
