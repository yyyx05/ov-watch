# OV-Watch Android App

OV-Watch 的 Android 伴侣应用。应用兼容手表原有的经典蓝牙 SPP 文本协议，
并优先使用固件新增的 `OV+DATA` 单行遥测帧；旧固件会自动回退到 `OV+SEND`。

## 当前能力

- 获取已配对的经典蓝牙设备并连接 KT6368
- 发送 `OV`、`OV+DATA`/`OV+SEND` 和 `OV+ST=yyyyMMddHHmmss`
- 解析步数、心率、环境温湿度和手表时间
- 自动轮询并用 SQLite 保存历史记录
- 健康总览、今日/7 天/30 天历史趋势、设备管理和调试日志界面
- 历史曲线按时间段聚合，原始采样在本机保留 90 天
- 原创 OV Health 启动图标、自适应图标和启动画面
- 进入设备页时检查 Android 蓝牙状态和“附近设备”权限
- 意外断线后指数退避自动重连（最多 5 次）
- App 进入后台时暂停轮询，返回前台后立即恢复
- 校时等待手表 `TIMESETOK` 确认，期间禁用重复点击、暂停自动采样
- 不展示固件未实现的 SpO2 默认值；首页将位置用于可回看的计时记录
- 可保存个人步数目标，健康首页与达标统计使用同一目标
- 心率、步数、环境温度、环境湿度四类历史；摘要、采样明细和用户主动复制 CSV
- 记住成功连接过的常用手表，默认隐藏耳机等无关蓝牙设备
- 离线显示上次采样并标注缓存时间，连接诊断中可查看手机/手表时间和复制日志
- 新固件秒表：实时运行/暂停状态，结束记录同步到手机，按用途标签及备注整理

## 秒表与计时历史

“计时”页显示手表实际返回的秒表状态，不是手机另开的计时器。请在手表上
开始、暂停/继续，最后复位结束；暂停可继续，不会被当成一次新的完成记录。
“历史 → 计时记录”可离线查看已导入手机的记录，并添加运动、学习等用途及备注。

秒表需要支持 `OV+CAP` / `OV+SW` / `OV+SWLOG` 的新固件。旧固件仍可读健康数据，
App 会提示其尚不支持计时同步，不会凭空生成计时记录。第一版手表仅在 RAM 中
保留最近 8 次已结束记录：蓝牙断开后可以在同一次开机内补传，重启/断电会丢失
尚未同步的记录，超过容量会覆盖最旧记录。手机已保存的记录不受手表重启影响。
记录结束时间来自手表 RTC，若尚未校时可能不准；时长使用独立计时状态。

健康数据库升级会保留已有采样，新增本机偏好设置；秒表使用独立数据库。
CSV 目前通过用户点击复制到系统剪贴板，不会自动上传或发送给其他人。

## 开发环境

蓝牙依赖要求 Flutter 3.44 或更新版本。本机当前工具链统一安装在 D 盘：

- Flutter：`D:\DevTools\flutter`
- JDK 21：`D:\DevTools\Java\jdk-21.0.12.1+1`
- Android SDK：`D:\DevTools\Android\Sdk`
- Pub/Gradle 缓存：`D:\DevTools\PubCache`、`D:\DevTools\GradleCache`

重新打开终端以读取已配置的用户环境变量，然后在本目录执行：

```powershell
flutter pub get
flutter analyze
flutter test
flutter build apk --debug
flutter run
```

若从 Codex Windows 受控终端构建时出现 `Unable to establish loopback
connection`，可仅为当前终端指定短临时目录后重试：

```powershell
$env:TEMP = 'D:\jtmp'
$env:TMP = 'D:\jtmp'
```

首次运行前，先在 Android 系统蓝牙设置中与 KT6368 配对。应用使用标准
SPP UUID，蓝牙权限由 `flutter_classic_bluetooth` 插件清单合并提供。
Android 12 及以上需授予“附近设备”权限中的连接和扫描权限：当前蓝牙库会在
连接前停止发现，因此仅有连接权限仍会报 `BLUETOOTH_SCAN` 权限错误。
连接后，App 发送不带换行的 `OV` 并等待 `OK`，再开始采样。联调时先断开
蓝牙调试助手，避免它占用手表连接。
校时前需在手表“设置 → 日期时间”中开启“同步APP”；发送命令不等于设置成功，
App 只在收到手表确认后显示成功，超时会提示检查手表开关。

2026-10-07 已在 Android 14 真机验证旧协议实时回包、首页显示及 SQLite
历史写入。当前只保存手机连接期间收到的数据，不会补齐断开期间的手表历史。
长时间运行、意外断线重连和计步变化仍需继续真机验收。

## 实施顺序

1. 现有协议连接、健康总览和本地历史（当前阶段）
2. 真机联调和后台长期运行验证（重连与前后台轮询已实现）
3. 手表设置、通知转发、天气和音乐控制
4. 在单行遥测 v1 的基础上增加请求序号、错误码和主动推送
5. OTA 升级：版本校验、用户确认、进度与失败恢复

OTA 放在最后，是因为升级中断可能让 APP 区不可启动，需要先把普通通信
和设备识别验证稳定。

当前遥测帧格式见 [`../docs/bluetooth-protocol.md`](../docs/bluetooth-protocol.md)。
