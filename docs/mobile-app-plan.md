# OV-Watch 手机 App 实施方案

## 产品目标

Android 首发，使用 KT6368 的经典蓝牙 SPP。App 负责更清晰地展示实时数据、
保存历史记录，并逐步承担手表设置、通知、天气、音乐和固件升级等伴侣功能。

界面借鉴成熟健康 App 的信息层级和交互习惯，但使用 OV-Watch 自己的颜色、
图标和组件，不复制华为运动健康的品牌素材或像素级布局。

## 交付顺序

### 1. 连接、总览和历史

- Android 已配对设备列表
- KT6368 SPP 连接与断开
- 兼容 `OV`、`OV+SEND`、`OV+ST`
- 实时步数、心率、环境温湿度
- SQLite 本地历史与今日/7 天/30 天趋势图（已实现，保留 90 天）
- 原始 TX/RX 调试日志

这一阶段不要求修改固件，能最早形成可在真机验证的完整闭环。

### 2. 稳定性和后台体验

- 自动重连与连接状态恢复（已实现，待真机压测）
- App 前后台切换处理（已实现）
- 采样节流和历史曲线聚合（已实现）
- 手表休眠/唤醒后的串口恢复测试
- 异常、权限和蓝牙关闭提示（已实现）

### 3. 双向伴侣功能

- 抬腕、亮度、熄屏时间等设置
- 手机通知转发到手表
- 天气同步
- 音乐播放控制和找手机

这些能力需要新增固件命令，届时应将调试打印与业务通信分开。

### 4. 协议 v1

当前文本协议可继续用于兼容模式。出现通知长文本、设置项和主动推送后，再新增
带版本、消息类型、长度、请求序号和错误码的协议。长度字段用于处理 RFCOMM
分片；OTA 数据另加校验，以发现传输中断或损坏。

### 5. OTA

复用现有 Bootloader/YModem，但必须先确认：

- 固件型号和版本匹配
- 用户明确确认升级
- 传输进度和超时
- 中断后仍可重新进入 Bootloader
- 成功启动新 APP 后再报告完成

## 当前数据边界

- AHT21 是环境温湿度，不标注为体温。
- EM7028 心率当前只在手表心率页面测量，不承诺全天连续心率。
- SpO2 固件分支尚未实现，App 不展示默认值 99 为真实结果。
- 当前 `OV+SEND` 未返回电量、海拔和罗盘数据；加入这些卡片前需要扩展协议。
